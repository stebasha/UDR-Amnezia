# План проверки 1.4.x на роутере

Цель: убедиться, что обновление ставится одной командой, ничего не ломает в UniFi, а веб-панель работает полностью.
Каждый шаг: что сделать → что должно получиться → что прислать, если не так.
Отмечайте результат: ✅ / ❌ (+ скриншот или вывод).

## 0. Подготовка (2 минуты)

```bash
python3 --version                  # нужен Python 3.7+; если команды нет — панель не запустится, напишите
cat /data/awg/VERSION              # текущая версия
awgctl status                      # всё работает до обновления
ss -ltn | grep -E ':4443 '         # порт панели свободен (пусто)
```

## 1. Обновление до 1.4 одной командой

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/stebasha/UDR-Amnezia/main/install.sh) --update
```

- ✅ в конце: «после обновления всё работает: набор 1.4.0» и «эталон правил обновлён».
- ✅ `cat /data/awg/.channel` → `AWG_BRANCH=main` (дальнейшие обновления из панели берутся с этой ветки).
- ❌ если «Откат обновления» — пришлите весь вывод.

Установщик в конце предложит включить веб-панель (Enter = да). Если отказались — включить позже:

```bash
/data/awg/install.sh --web
```

Мастер спросит порт (Enter = 4443), имя и пароль администратора. В конце покажет адрес.

## 2. UniFi не задет

- ✅ Веб-интерфейс UniFi открывается как раньше (https://IP_роутера), устройства онлайн, интернет есть.
- ✅ `ss -ltnp | grep 4443` — слушает только LAN-адрес (например `192.168.1.1:4443`), не `0.0.0.0`.
- ✅ `awgctl drift` → «правила и службы совпадают с эталоном».
- ✅ `systemctl status awg-web --no-pager | head -5` — active (running).

## 3. Вход и безопасность

1. Откройте `https://IP_роутера:4443/`. Предупреждение о сертификате — нормально при самоподписанном.
2. ✅ Вход с паролем. Неверный пароль 5 раз подряд → «вход заблокирован на 15 минут» (проверяйте с телефона, чтобы не заблокировать себя).
3. Настройки → Пользователи и 2FA → «Включить 2FA», отсканировать QR → ✅ выход и вход просят код.
4. ✅ Настройки → Пользователи → «Активные сеансы»: видны ваши браузеры; «Завершить» выкидывает другой браузер.

## 4. Сертификат UniFi

Настройки → Панель и сертификат.

- ✅ В таблице «Найден сертификат UniFi» есть ваш сертификат (имя, издатель, срок).
- Выберите «Сертификат UniFi», «Сохранить и перезапустить панель».
- ✅ Через 5–10 с страница откроется заново. Откройте панель по имени из сертификата: `https://ваше.имя:4443/` — без предупреждения браузера.
- ❌ если сертификат не найден — пришлите вывод:
  ```bash
  ls -la /data/unifi-core/config/ /data/unifi-core/config/http/ 2>&1 | head -40
  grep -h ssl_certificate /data/unifi-core/config/http/*.conf 2>/dev/null
  ```

## 5. Обзор

- ✅ Плитки, схема, график трафика за 10 минут двигается, через ~час появляются данные за сутки.
- ✅ «Клиенты в туннеле»: устройства, которые сейчас ходят через PBR (с именами из DHCP).
- ✅ «Доступность каналов»: полосы заполняются раз в минуту.

## 6. Туннели: редактирование и загрузка

1. Туннели → «Настроить» у запасного (или дополнительного) туннеля → «Параметры».
   - Поменяйте `PersistentKeepalive` (например 25 → 21) → «Проверить и применить» → ✅ видно различие в одну строку → «Применить» → ✅ «Конфиг применён», handshake есть.
   - «История» → ✅ две версии; «Сравнить»; «Вернуть» прежнюю → ✅ вернулось.
2. Неверные значения: `Endpoint` = `abc` → ✅ «не принято», конфиг не изменился.
3. «Качество»: ✅ полоса доступности, графики RTT и потерь (если включено переключение по качеству); «Замерить скорость» 10 МБ → ✅ числа загрузки/отдачи.
4. Импорт: Туннели → «Импорт».
   - Перетащите `.conf` (например, запасной конфиг с компьютера) или вставьте ссылку `vpn://` из AmneziaVPN → «Разобрать» → ✅ протокол, сервер, адрес; предупреждение, если сервер уже используется.
   - «Куда: новый дополнительный туннель», имя `awgtest` → «Применить» → ✅ появилась карточка, handshake.
   - «Настроить» → «Ещё» → «Удалить awgtest» → ✅ карточка пропала, `awgctl drift` чистый.
5. «Ещё» → «Скачать .conf» с паролем → ✅ файл скачан (удалите его потом).
6. «Активировать» запасной → ✅ трафик через него (на устройстве под PBR 2ip.io показывает IP запасного); «Автовыбор канала» → ✅ вернулся основной (после RECOVER_SEC).

## 7. Маршрутизация

- Домены через туннель: добавьте `2ip.io` → «Применить» → ✅ сообщение о перезапуске служб; Инструменты → «Проверка домена» `2ip.io` → ✅ «в TUN_DOMAINS», адреса в наборе AWG_DOM (после открытия сайта с устройства). Потом уберите.

## 8. Инструменты

- ✅ Диагностика: итог «причин не найдено» (или понятная причина).
- ✅ Скорость: «все туннели и WAN», 10 МБ → три строки в истории.
- ✅ Ping 1.1.1.1 через основной туннель и через WAN; трассировка (если на роутере есть traceroute).
- ✅ Сверка с эталоном: «совпадают». Для проверки: `systemctl restart awg-guard` не должен давать расхождений.
- ✅ Отчёт для помощи → «Скачать отчёт».

## 9. Настройки

- Резервные копии: создать с паролем → ✅ в списке; «Проверить» с паролем → ✅ «копия читается»; скачать.
- Система и обновление: «Экспорт настроек» → ✅ JSON без ключей; «Импорт настроек» этого же файла → ✅ «изменений нет».
- «Проверить обновления» → ✅ «Установлена последняя версия …» с номером из `VERSION` ветки, с которой ставили (`/data/awg/.channel`).
- Telegram: «Тестовое сообщение» → ✅ пришло.
- Журналы → «Действия в панели» → ✅ видны ваши действия.

## 10. Устойчивость

- `systemctl restart awg-web` → ✅ панель вернулась за ~5 с, сеанс надо войти заново (сеансы в памяти).
- Перезагрузка роутера (когда удобно) → через 2–3 минуты ✅ панель открывается, `awgctl selftest` без FAIL.

## 11. Что нового в 1.4.1

1. **Бот.** Напишите боту `/menu` → ✅ состояние и кнопки. «Каналы» → запасной → «Сделать активным» → ✅ просит подтверждение → «Да» → ✅ переключился; «Вернуть автовыбор». «Роутер», «Клиенты», «Проверки → Диагностика» → ✅ ответы. «Уведомления → 🔕 1 час» → ✅ отметка «выключены до …».
2. **Второй человек.** Настройки → Telegram → «Только просмотр»: chat id второго человека → Сохранить. ✅ Ему приходят уведомления; кнопка «Сделать активным» у него отвечает «только администраторам». Узнать chat id: человек пишет боту `/start` — бот ответит его id.
3. **Роутер.** Нажмите плитку «Роутер» в обзоре → ✅ кольца процессора, памяти, диска, температуры; проверки; через час — графики за сутки.
4. **Качество канала.** Через 1–2 минуты после обновления ✅ в плитке Handshake «RTT … · потери …% (TCP)», полоса доступности основного канала зелёная.
5. **Файлы.** Инструменты → «Отчёт для помощи» → ✅ файл скачивается сам. Журналы → «Скачать». В выводе любой команды — кнопки «Копировать» и «Скачать».
6. **Язык.** Кнопка EN в верхней строке → ✅ интерфейс на английском; RU — обратно.

## 12. Что нового в 1.4.2

1. **Команды без алиасов.** С компьютера: `plink -batch -load СЕССИЯ awgctl status` (или `ssh root@IP_роутера awgctl status`) → ✅ состояние, а не `awgctl: command not found`. `ls -l /usr/local/bin/awgctl` → ссылка на `/data/awg/awgctl.sh`.
2. **Самопроверка.** `awgctl selftest` на роутере, где часть служб выключена → ✅ нет WARN «установлен, но не запущен» для выключенных служб; без `LEAK_GUARD=yes` — INFO «защита … выключена», а не FAIL.
3. **Журнал служб.** `systemctl restart awg-notify; journalctl -u awg-notify -n 5` → ✅ нет `status=143` / `Failed`. `systemctl restart awg-failover; journalctl -u awg-failover -n 20` → ✅ нет `Cannot find device`.
4. **Выключение защиты из панели.** Настройки → Службы → `awg-guard` «Выключить» → ✅ в `awg.env` `LEAK_GUARD=no`; сохранение любой настройки маршрутизации не включает `awg-guard` обратно.
5. **Перезагрузка роутера** (когда удобно). Обзор → «Перезагрузить»:
   - неверный пароль → ✅ «текущий пароль неверен», роутер работает;
   - «Отмена» / Esc → ✅ ничего не происходит;
   - верный пароль → ✅ окно «Роутер перезагружается», через 5 с роутер уходит в перезагрузку, через 2–4 минуты страница открывается сама (нужен повторный вход);
   - ✅ в Telegram пришло «Перезагрузка роутера»; в «Журналы → События» — «Перезагрузка», в «Действия в панели» — `reboot`;
   - после загрузки ✅ `awgctl selftest` без FAIL, `awgctl drift` чистый.
   Та же кнопка есть на странице «Роутер».
