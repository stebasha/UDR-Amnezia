# Возможности установки (версия 1.4.1)

Все скрипты лежат в репозитории (`awg/` — роутер, `server/` — VPS). `install.sh` скачивает набор с GitHub, проверяет синтаксис, копирует файлы в `/data/awg` и включает только те службы, которые вы выбрали. Тот же набор описан для ручной установки в гайде `index.html`.

## 1. Основа: туннель AmneziaWG на UDR7

| Возможность | Как устроено |
|---|---|
| Проверка роутера | aarch64, UniFi OS, `/dev/net/tun`, нужные команды, место на `/data`, доступ к GitHub, время |
| Бинарники | только официальные исходники amnezia-vpn на закреплённых тегах; сборка на своём VPS по SSH или на любом Ubuntu/Debian (`server/awg-build-router.sh`); свой источник (папка или ссылка) — с проверкой SHA-256 по `SHA256SUMS` или введённым суммам, без сумм — только после подтверждения; проверка обоих файлов по `SHA256SUMS` и запуска на роутере; прежние версии сохраняются как `*.prev` |
| Сценарии | **A** — один туннель от провайдера; **B** — один туннель до своего VPS; **C** — основной + запасной |
| Конфиги | вставка в терминал или файлом; проверка секций, ключей, Endpoint, Address и обфускации; права 600 |
| Подъём туннеля | `up.sh`: директивы wg-quick убираются, имя сервера разрешает сам роутер (с запасным адресом), MTU из конфига или 1380 |
| Проверка туннеля | внешний IP через интерфейс (HTTPS: ICMP у многих операторов не ходит), handshake |
| Диагностика | tcpdump на WAN роутера и одновременно на VPS, вывод причины: порт у хостера, ключи, обфускация, DPI |
| Остатки старых установок | обычный WireGuard `wgbackup`, тестовые правила таблицы 300, тестовый DROP icmp, сторонний установщик `/data/awg-native`, ручные экземпляры сторожа |

## 2. Интеграция с PBR UniFi

- `awg-detect.sh` находит таблицу, метку, приоритет и профиль VPN Client («рельсу») и обновляет только эти ключи в `awg.env`.
- Фиктивный профиль-рельса генерируется, если правила PBR нет; установщик показывает шаги в UniFi.
- Сторож держит в таблице PBR `default dev awgX metric 5` и `blackhole default metric 200`, NAT MASQUERADE, TCPMSS, FORWARD.
- Смена метки или таблицы профилем UniFi обнаруживается (журнал сторожа, панель, аудит, самопроверка).

## 3. Надёжность

| Возможность | Как устроено |
|---|---|
| Автопереключение | 3 неудачные проверки подряд (~15 с) → первый живой канал по приоритету; возврат после `RECOVER_SEC` (600 с) стабильной работы |
| Kill switch | `blackhole` ставится при старте сторожа и остаётся при остановке и перезапуске |
| Несколько туннелей | `TUNNELS_EXTRA`, приоритет: основной, запасной, дополнительные |
| Качество канала | потери и RTT раз в 30 с; 3 плохие пробы подряд → здоровый канал; `MIN_DWELL` против «дёрганья» |
| Ручное управление | `awgctl switch <имя>` / `awgctl auto` |
| conntrack | при переключении сбрасываются записи, заNATенные на адрес прежнего туннеля |
| iptables `-w` | все вызовы ждут блокировку xtables; правило добавляется только при ответе «нет» (код 1); при занятой блокировке ничего не меняется |
| Дубликаты | `awgctl dedup` (и автоматически при старте сторожа и обновлении); аудит и самопроверка показывают дубликаты во всех таблицах и в `ip rule` |
| Атомарность | цепочки собираются целиком и подменяются; переходы в цепочки ровно одни; пропавшие цепочки восстанавливаются; блокировки между службой и ручным запуском |
| Безопасное обновление | файлы заменяются через временный файл и `mv`; вход в установщик — функция `main`; для обновления с 1.0/1.1 — «площадка» в файле |

## 4. Маршрутизация и защита

**Клиенты VPN-сервера роутера** (`subnets.sh`, служба `awg-subnets`): WireGuard Server, Teleport. `ip rule` 6100 (локальное остаётся локальным) и 6101 (интернет — в таблицу PBR), маршрут подсети в таблице PBR, проверка совпадения с LAN, лишние копии правил убираются.

**Защита от утечек** (`guard.sh`, служба `awg-guard`):
- помеченный PBR-трафик не выпускается ни в один WAN (цепочка первой в `filter FORWARD`);
- IPv6 помеченного трафика и клиентов VPN-сервера блокируется (`LEAK_V6=block`);
- список WAN только растёт: переподключение PPPoE защиту не снимает;
- предупреждение, если у WAN есть IPv6, а правил PBR для IPv6 нет.

**Трафик самого роутера и unifi.ui.com** (`self.sh`, служба `awg-self`, основа — awg-ui-fix):
- соединения роутера повторяют правила PBR UniFi по адресам назначения;
- unifi.ui.com из РФ: DNS домена через туннель, адреса облака Ubiquiti — в ipset и через туннель;
- мимо туннеля всегда: серверы туннелей (из всех конфигов), DNS роутера, частные сети, DHCP и широковещание, подсеть провайдера, ответы на входящие соединения;
- файл для dnsmasq проверяется `dnsmasq --test`; домены проверяются на корректность;
- `self.sh check` — проверка по пунктам, `self.sh reconnect` — перевод старых соединений.

**Домены через туннель и исключения**: `TUN_DOMAINS` для выбранных клиентов (`TUN_CLIENTS`), исключения `DIRECT_DOMAINS` и `DIRECT_SUBNETS`; при защите от утечек с `LEAK_V6=block` IPv6-адреса доменов через туннель отклоняются (устройства переходят на IPv4).

**MTU** (`mtu.sh`): максимальный пакет без фрагментации до сервера минус накладные расходы AmneziaWG; применение с копией конфига и откатом.

## 5. Управление и наблюдение

- `awgctl`: `status`, `switch`, `auto`, `events`, `stats`, `ip`, `selftest`, `mtu`, `backup`, `dedup`, `diagnose`, `domain`, `report`, `web`.
- `awgctl diagnose`: дерево причин с итогом «первая причина и команда исправления»; `awgctl domain ДОМЕН`: куда пойдёт сайт и где открывается; `awgctl report`: обезличенный отчёт.
- `awg-selftest`: службы, туннели, внешний IP, PBR и kill switch (`--full` — живая проверка), дубликаты, NAT, MTU, утечки, DNS, подсети, awg-self, домены, место, время, права, манифест.
- Панель `awgs` при входе по SSH: состояние, предупреждения, все туннели, службы, события, шпаргалка.
- Аудит `awg-audit`: службы и юниты, процессы, туннели, маршрутизация, дубликаты, файлы и права, ключи в истории команд.
- Метрики Prometheus (`awg-metrics`): файл или HTTP на LAN-адресе роутера.

## 5а. Веб-панель (awg-web)
- Адрес `https://IP_РОУТЕРА:4443/`, только LAN; включение: `install.sh --web`.
- Разделы: Обзор, Туннели (редактор с формой, текстом, историей версий, качеством и экспортом; импорт `.conf` и `vpn://`), Клиенты, Маршрутизация, Инструменты (диагностика, скорость, ping/трассировка, drift, домен, MTU), Журналы, Настройки (2FA, сеансы, сертификат UniFi, копии с проверкой, перенос настроек, обновление с откатом).
- Пользователи: `awgctl web passwd ИМЯ`, `awgctl web users`, `awgctl web totp-off ИМЯ`; сертификат: `awgctl web cert`.
- Безопасность: PBKDF2-SHA256, TOTP, CSRF, проверка Origin и Host, блокировка подбора, журнал действий (`/data/awg/web/audit.log`), CSP, без внешних ресурсов.

## 5в. Роутер и Telegram
- Страница «Роутер»: процессор, память, диск, температура, conntrack, графики за сутки, проверки с советами и прогнозом заполнения /data, OOM и ошибки I/O, процессы.
- Бот с кнопками (`bot.py`): меню, переключение с подтверждением, проверки, роутер, клиенты, тишина; администраторы (`TG_CHAT`) и «только просмотр» (`TG_VIEWERS`); тревоги о железе и службах.
- Панель на русском и английском.

## 5б. Сверка и обновление
- `awgctl drift`: эталон правил и служб, отличия с пометкой «набор»/«UniFi», `repair` перезапускает только службы набора.
- `install.sh --update`: копия, проверка после обновления, автоматический откат при сбое; ветка запоминается в `/data/awg/.channel`.

## 6. Telegram

- Уведомления: переключение, деградация, ручное переключение, возврат, отказ всех каналов, восстановление; доставка через туннели с запасным путём через WAN, очередь при полном отказе; токен не виден в списке процессов.
- Суточный и недельный отчёты.
- Бот (только ваш чат): `/status`, `/ip`, `/switch`, `/auto`, `/events`, `/stats`, `/selftest`, `/restart`, `/help`; предупреждения о месте, службах, подсети VPN-сервера, времени.

## 7. Обслуживание

- Резервные копии (`backup.sh`): AES-256 + PBKDF2, 7 последних, проверка и восстановление.
- `--restore` после обновления прошивки; автовосстановление через `/data/on_boot.d` (нужен обработчик on_boot.d).
- `--update`, `--self-update` (SHA-256), `--verify` (манифест), `--dry-run`, `--record` / `--answers`.
- Обновление бинарников из меню с проверкой и запасными копиями.
- Удаление (`--uninstall`): службы, правила, туннели, команды, баннер; `--purge` — и папка с ключами.

## 8. Свой VPS

- Автонастройка по SSH: сборка из официальных исходников, ключи, обфускация (случайная или из рабочего конфига), автозапуск, `client.conf` на роутер.
- Защита: автообновления, fail2ban, вход по ключам (ключ роутера может быть добавлен на VPS); ufw не включается.
- Смена ключей туннеля с автоматическим откатом.
- Аудит VPS (`audit-server.sh`).

## 9. Качество

- Тесты на заглушках без роутера: `bash tests/run.sh` (сторож, guard, awg-self, iptables под блокировкой, удаление, установщик, обновление со старых версий).
- CI: синтаксис, shellcheck, тесты, `install.sh.sha256`, совпадение гайда со скриптами, отсутствие сторонних источников бинарников.
