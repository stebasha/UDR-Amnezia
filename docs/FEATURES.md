# Возможности установки (версия 1.5)

Все скрипты лежат в репозитории (`awg/` — роутер, `server/` — VPS). `install.sh` скачивает набор с GitHub, проверяет синтаксис, копирует файлы в `/data/awg` и включает только те службы, которые вы выбрали. Тот же набор описан для ручной установки в гайде `index.html`.

## 1. Основа: туннель AmneziaWG на UDR7

| Возможность | Как устроено |
|---|---|
| Проверка роутера | aarch64, UniFi OS, `/dev/net/tun`, нужные команды, место на `/data`, доступ к GitHub, время |
| Бинарники | только официальные исходники amnezia-vpn на закреплённых тегах; сборка на своём VPS по SSH или на любом Ubuntu/Debian (`server/awg-build-router.sh`); свой источник (папка или ссылка) — с проверкой SHA-256 по `SHA256SUMS` или введённым суммам, без сумм — только после подтверждения; проверка обоих файлов по `SHA256SUMS` и запуска на роутере; прежние версии сохраняются как `*.prev`; `--bins-check` и кнопка в панели сравнивают с последними релизами amnezia-vpn, `--bins-update` обновляет с откатом, если туннель теряет handshake |
| Сценарии | **A** — один туннель от провайдера; **B** — один туннель до своего VPS; **C** — основной + запасной |
| Конфиги | вставка в терминал или файлом; проверка секций, ключей, Endpoint, Address и обфускации; права 600 |
| Подъём туннеля | `up.sh`: директивы wg-quick убираются, имя сервера разрешает сам роутер (с запасным адресом), MTU из конфига или 1380 |
| Проверка туннеля | внешний IP через интерфейс (HTTPS: ICMP у многих операторов не ходит), handshake |
| Диагностика | tcpdump на WAN роутера и одновременно на VPS, вывод причины: порт у хостера, ключи, обфускация, DPI |
| Остатки старых установок | обычный WireGuard `wgbackup`, тестовые правила таблицы 300, тестовый DROP icmp, сторонний установщик `/data/awg-native`, ручные экземпляры сторожа |

## 2. Интеграция с PBR UniFi

- `awg-detect.sh` находит таблицу, метку, приоритет и профиль VPN Client («рельсу») и обновляет только эти ключи в `awg.env`.
- Фиктивный профиль-рельса генерируется, если правила PBR нет; установщик показывает шаги в UniFi.
- Сторож держит в таблице PBR `default dev awgX metric 5` и `blackhole default metric 200`, NAT MASQUERADE, TCPMSS, FORWARD.
- Смена метки или таблицы профилем UniFi обнаруживается (журнал сторожа, панель, аудит, самопроверка).

## 3. Надёжность

| Возможность | Как устроено |
|---|---|
| Автопереключение | 3 неудачные проверки подряд (~15 с) → первый живой канал по приоритету; возврат после `RECOVER_SEC` (600 с) стабильной работы; давно лежащий основной канал проверяется реже (раз в 30–60 с), чтобы проход не растягивался |
| Kill switch | `blackhole` ставится при старте сторожа и остаётся при остановке и перезапуске |
| Несколько туннелей | `TUNNELS_EXTRA`, приоритет: основной, запасной, дополнительные |
| Качество канала | потери и RTT раз в 30 с; 3 плохие пробы подряд → здоровый канал; `MIN_DWELL` против «дёрганья» |
| Ручное управление | `awgctl switch <имя>` / `awgctl auto` |
| conntrack | при переключении сбрасываются записи, заNATенные на адрес прежнего туннеля |
| iptables `-w` | все вызовы ждут блокировку xtables; правило добавляется только при ответе «нет» (код 1); при занятой блокировке ничего не меняется |
| Дубликаты | `awgctl dedup` (и автоматически при старте сторожа и обновлении); аудит и самопроверка показывают дубликаты во всех таблицах и в `ip rule` |
| Атомарность | цепочки собираются целиком и подменяются; переходы в цепочки ровно одни; пропавшие цепочки восстанавливаются; блокировки между службой и ручным запуском |
| Экономия ресурсов (1.7.1) | фоновые службы сверяют правила по одному снимку цепочек за проход и почти не запускают внешних процессов; пока по каналу идёт трафик (`CHECK_RX_MIN` байт за проход), HTTPS-проверка не нужна — настоящая не реже `CHECK_MAX_AGE` (60 с); верная таблица маршрутов не переписывается; панель, бот, HA, метрики и уведомления — с `Nice=5`; фоновых проверок в панели не больше четырёх сразу, в боте — двух |
| Безопасное обновление | файлы заменяются через временный файл и `mv`; вход в установщик — функция `main`; обновление поддерживается с 1.2 и новее |

## 4. Маршрутизация и защита

**Клиенты VPN-сервера роутера** (`subnets.sh`, служба `awg-subnets`): WireGuard Server, Teleport. `ip rule` 6100 (локальное остаётся локальным) и 6101 (интернет — в таблицу PBR), маршрут подсети в таблице PBR, проверка совпадения с LAN, лишние копии правил убираются.

**Защита от утечек** (`guard.sh`, служба `awg-guard`):
- помеченный PBR-трафик не выпускается ни в один WAN (цепочка первой в `filter FORWARD`);
- IPv6 помеченного трафика и клиентов VPN-сервера блокируется (`LEAK_V6=block`);
- список WAN только растёт: переподключение PPPoE защиту не снимает;
- предупреждение, если у WAN есть IPv6, а правил PBR для IPv6 нет.

**Трафик самого роутера и unifi.ui.com** (`self.sh`, служба `awg-self`, основа — awg-ui-fix):
- соединения роутера повторяют правила PBR UniFi по адресам назначения; маршрут «весь интернет» (без условия на назначение) не повторяется — весь трафик роутера, включая DNS, ушёл бы в туннель (1.7.1);
- unifi.ui.com из РФ: DNS домена через туннель, адреса облака Ubiquiti — в ipset и через туннель;
- мимо туннеля всегда: серверы туннелей (из всех конфигов), DNS роутера, частные сети, DHCP и широковещание, подсеть провайдера, ответы на входящие соединения;
- файл для dnsmasq проверяется `dnsmasq --test`; домены проверяются на корректность;
- `self.sh check` — проверка по пунктам, `self.sh reconnect` — перевод старых соединений.

**Домены через туннель и исключения**: `TUN_DOMAINS` для выбранных клиентов (`TUN_CLIENTS`), исключения `DIRECT_DOMAINS` и `DIRECT_SUBNETS`; при защите от утечек с `LEAK_V6=block` IPv6-адреса доменов через туннель отклоняются (устройства переходят на IPv4).

**MTU** (`mtu.sh`): максимальный пакет без фрагментации до сервера минус накладные расходы AmneziaWG; применение с копией конфига и откатом.

## 5. Управление и наблюдение

- `awgctl`: `status`, `switch`, `auto`, `events`, `stats`, `ip`, `ping`, `selftest`, `mtu`, `backup`, `dedup`, `diagnose`, `domain`, `report`, `web`, `drift`.
- `awgctl ping`: задержка через туннель или WAN; если ICMP режется — время TCP-подключения.
- `awgctl diagnose`: дерево причин с итогом «первая причина и команда исправления»; `awgctl domain ДОМЕН`: куда пойдёт сайт и где открывается; `awgctl report`: обезличенный отчёт.
- `awg-selftest`: службы, туннели, внешний IP, PBR и kill switch (`--full` — живая проверка), дубликаты, NAT, MTU, утечки, DNS, подсети, awg-self, домены, место, время, права, манифест.
- Панель `awgs` при входе по SSH: состояние, предупреждения, все туннели, службы, события, шпаргалка.
- `awgctl`, `awg-selftest`, `awgs` работают и без интерактивной оболочки (`ssh роутер awgctl status`, plink, cron): ссылки в `/usr/local/bin`, после обновления прошивки их возвращает `awg-restore.sh`.
- Аудит `awg-audit`: службы и юниты, процессы, туннели, маршрутизация, дубликаты, файлы и права, ключи в истории команд.
- Метрики Prometheus (`awg-metrics`): файл или HTTP на LAN-адресе роутера.

## 5а. Веб-панель (awg-web)
- Адрес `https://IP_РОУТЕРА:4443/`, только LAN; включение: `install.sh --web`.
- Разделы: Обзор, Туннели (редактор с формой, текстом, историей версий, качеством и экспортом; импорт `.conf` и `vpn://`), Клиенты, Маршрутизация, Инструменты (диагностика, скорость, ping/трассировка, drift, домен, MTU), Журналы, Настройки (2FA, сеансы, сертификат UniFi, копии с проверкой, перенос настроек, обновление с откатом).
- Перезагрузка роутера из обзора и со страницы «Роутер»: подтверждение паролем, отложенный на 5 с `reboot`, запрет во время обновления, событие в журнале и сообщение в Telegram; страница сама переподключается, когда роутер вернётся.
- Пользователи: `awgctl web passwd ИМЯ`, `awgctl web users`, `awgctl web totp-off ИМЯ`; сертификат: `awgctl web cert`.
- Безопасность: PBKDF2-SHA256, TOTP, CSRF, проверка Origin и Host, блокировка подбора, ограничение частоты API с адреса (`WEB_RATE` / `WEB_RATE_POST` в web.conf, по умолчанию 1200 и 240 в минуту, сверх — 429 с Retry-After), время жизни сеансов (без активности и всего; «Пользователи и 2FA → Активные сеансы»), пароль для перезагрузки, удаления туннеля, импорта настроек, времени сеансов и изменений на VPS, журнал действий (`/data/awg/web/audit.log`, ротация в `audit.log.1` после 512 КБ), CSP, без внешних ресурсов.

## 5в. Роутер и Telegram
- Страница «Роутер»: процессор, память, диск, температура, conntrack, графики за сутки, проверки с советами и прогнозом заполнения /data, OOM и ошибки I/O, процессы.
- Бот с кнопками (`bot.py`): меню, переключение с подтверждением, проверки, роутер, клиенты, тишина; администраторы (`TG_CHAT`) и «только просмотр» (`TG_VIEWERS`); тревоги о железе и службах.
- Панель на русском и английском.

## 5г. Home Assistant и API
- MQTT discovery (`awg-ha`): датчики каналов и роутера, выбор канала, перезапуск туннелей, перезагрузка (по желанию); настройки в панели.
- Токены API (чтение / управление) для REST: Home Assistant, скрипты, мониторинг.
- Сеансы панели переживают перезапуск и обновление.

## 5б. Сверка и обновление
- `awgctl drift`: эталон правил и служб, отличия с пометкой «набор»/«UniFi», `repair` перезапускает только службы набора.
- `install.sh --update`: копия, проверка после обновления, автоматический откат при сбое; ветка запоминается в `/data/awg/.channel`.

## 5г. Свой VPS

- Мастер: адрес и пароль root один раз → ключ роутера на VPS (пароль через SSH_ASKPASS, нигде не сохраняется), сборка AmneziaWG, сервер, конфиг клиента → туннель с проверкой handshake; конфиг клиента на VPS удаляется.
- Обновление бинарников роутера из панели: сборка на своём VPS, SHA256SUMS, откат по handshake.
- 3x-ui ≥ 3.8.5: подключение AmneziaWG 3.1 по API-токену, закрытый ключ клиента только на роутере, конфиг 3.1 из ответа API, удаление туннеля вместе с подключением.
- Несколько панелей 3x-ui (#32): список подключений AmneziaWG с клиентами и трафиком; привязка работающего туннеля по ключу сервера и порту; «Обновить из 3x-ui» (параметры из 3x-ui, ключ роутера прежний, откат); подключение к клиенту, ключ которого хранит 3x-ui; адрес сервера с учётом узлов 3x-ui; совместимость с 3x-ui 3.10 (settings объектом).
- Несколько своих VPS (#32): `vps.d/ID.env`, `vps.sh --vps ID`, выбор в панели; смена ключей и обфускации — только для туннелей на порт `awg-server`, не для 3x-ui.
- Маршруты (#22): профиль VPN Client UniFi → своя таблица, метка и цепочка туннелей; сторож `awg-failover-ID` (`failover.sh --route ID`), `route.d/ID.env`, `ROUTE_ONLY`; защита меток в WAN; самопроверка; восстановление после прошивки через `.units`.
- IPv6 через туннель (#23, `LEAK_V6=route`): `ip -6 rule` (proto 99) и маршрут IPv6 в таблице PBR на активный туннель с IPv6, NAT66/MSS/FORWARD, unreachable без IPv6; сброс conntrack IPv6 при переключении.
- Автоподбор обфускации (#33): `obfs-tune.sh run|apply|show`, режимы client (Jc/Jmin/Jmax) и server (с VPS, `vps.sh obfs --file`), замеры handshake/потерь/задержки/скорости, оценка, возврат исходного набора, `tune.tsv`.
- Автоподбор при деградации (#36, `AUTO_TUNE`): `autotune_tick()` в мониторе бота раз в минуту; неактивный туннель (`active_tunnels()` всех маршрутов) с handshake > 180 с или `LOSS_` ≥ `QUALITY_LOSS` дольше `AUTO_TUNE_AFTER` → `obfs-tune.sh run T client 5` (служба awg-tune), не чаще `AUTO_TUNE_EVERY`; итог из `tune.tsv` → предложение с кнопкой `tap:T:N` (только администраторы, только предложенный набор), `tune_apply()` без пароля панели; `autotune.json`, события `tune`.
- Списки и GeoIP (#38, `LISTS_MODE=off|blocked|geoip`): `lists.sh update|load|status|json|due`; источники `LIST_URLS` (antifilter.download) и `GEO_URL` (ipverse/country-ip-blocks, `GEO_COUNTRIES`); скачивание напрямую, иначе через туннель; проверка формата (IPv4 CIDR, без частных сетей, минимум строк), прежний список при ошибке; атомарная загрузка в ipset `AWG_LIST`/`AWG_GEO` (restore + swap); `guard.sh` снимает метку PBR основного и дополнительных маршрутов в `AWG_DIRECT_POST`; пустой набор — правила нет (всё через туннель); обновление раз в сутки и при смене стран/источников; панель «Маршрутизация → Списки и GeoIP», `/api/lists`, самопроверка и диагностика. Предупреждение, если в UniFi нет маршрута PBR «весь интернет» в наш туннель (`lists.sh full` — правила `UBIOS_PREROUTING_PBR` с меткой туннеля без условия на назначение; `-1` — цепочки нет): тогда режим ни на что не влияет (1.7.1). Маршруты UniFi по доменам и адресам с меткой нашего туннеля и `TUN_DOMAINS` остаются в туннеле при любом режиме: их IPv4-наборы собраны в list:set `AWG_KEEP` (сверка раз в 60 с), правило снятия метки их исключает (1.7.1). Маршрут UniFi с Kill Switch ставит метку с флагом `0x10000` (`0x6b0000/0x7f0000`): снятие метки (исключения, списки, GeoIP) снимает и флаг, иначе трафик уходил в blackhole UniFi; флаг `0x10000` с меток наших маршрутов сторож снимает с пакета и с метки соединения (`CONNMARK`) первым правилом `AWG_DIRECT_POST`: иначе UniFi отбрасывает DNS к роутеру (`UBIOS_DNS_PBR_JUMP`, ждёт DNS-сервер VPN-клиента, а у профиля-«рельсы» его нет), а ответы фильтра контента (127.0.0.1:1053) не доходят (1.7.1).
- Перехват DNS (#39, `DNS_INTERCEPT`, `DNS_CLIENTS`, `DNS_BLOCK_DOT`): `guard.sh` — цепочка `AWG_DNS_PRE` последней в nat PREROUTING (REDIRECT UDP/TCP 53 к чужим адресам на dnsmasq роутера, после перехвата фильтра контента UniFi), `AWG_DNS_FWD` в FORWARD сразу после `AWG_GUARD` (REJECT 853; для всей LAN — ещё IPv6 DNS/DoT к чужим серверам); вместе с `DNS_ALL_TUNNEL` — DNS устройств через туннель.
- Маршруты в боте и HA (#40): экраны `m:rt`/`r:ID`, команды `/routes`, `/route ID канал|auto`, подтверждение `rtq`/`rtw`; HA — `sensor route_ID_active`, `binary_sensor route_ID_up`, `select route_ID_mode` (тема `…/set/route/ID`), удаление исчезнувших сущностей пустыми retained-конфигами.
- Отчёт (#41): `report_data(7|30)` из часовых сводок (новые поля `am` — минуты активности каналов, `ra` — минуты маршрутов по туннелям), `speed.json`, событий (основной и `stats_from_events(days, route)`) и `traffic.json`; `/api/report`, карточка «Отчёт» в обзоре, `/week` и недельный отчёт бота. Учёт трафика: `AWG_ACC` (mangle FORWARD, первым), `-j SET --add-set` + `-m set` со счётчиками `AWG_ACC_UP`/`AWG_ACC_DN`, сбор раз в 10 минут, сброс счётчика без отрицательных приращений, `--uninstall` убирает.

- `vps.sh` / `awgctl vps` / «Настройки → Свой VPS»: вход на VPS ключом роутера (BatchMode, свой known_hosts в `/data/awg/ssh`), состояние сервера (audit-server.sh, только чтение), версии AmneziaWG на VPS против последних релизов amnezia-vpn.
- Обновление AmneziaWG на VPS: сборка из официальных исходников, `*.prev`, проверка handshake туннелей к VPS, откат.
- Смена ключей и параметров обфускации (Jc..H4) согласованно на VPS и роутере: копии, проверка handshake и интернета, откат обеих сторон; только для туннеля с Endpoint = VPS; AWG 2.0 (диапазоны H) не трогается. Из панели — с паролем, отдельной службой с журналом.

## 6. Telegram

- Уведомления: переключение, деградация, ручное переключение, возврат, отказ всех каналов, восстановление; доставка через туннели с запасным путём через WAN, очередь при полном отказе; токен не виден в списке процессов.
- Вебхук (POST JSON с уровнем critical/warning/ok/info, необязательный заголовок) и ntfy (приоритет по уровню, токен): те же события, работают и без Telegram; адрес, заголовок и токен хранятся в `hooks.env` (600), в браузер не возвращаются и не видны в списке процессов.
- Суточный и недельный отчёты.
- Бот (только ваш чат): `/status`, `/ip`, `/switch`, `/auto`, `/events`, `/stats`, `/selftest`, `/restart`, `/help`; предупреждения о месте, службах, подсети VPN-сервера, времени.

## 7. Обслуживание

- Резервные копии (`backup.sh`): AES-256 + PBKDF2, 7 последних, проверка и восстановление. Автокопия по расписанию (ежедневно/еженедельно): проверка расшифровкой, отправка на свой VPS (scp ключом роутера, сверка SHA-256 на сервере, хранение N последних) и/или документом администраторам в Telegram; итог — в истории, журнале событий и `awgctl selftest`, сбой — сообщением в Telegram.
- `--restore` после обновления прошивки; автовосстановление через `/data/on_boot.d` (нужен обработчик on_boot.d).
- `--update`, `--self-update` (SHA-256), `--verify` (манифест), `--dry-run`, `--record` / `--answers`.
- Обновление бинарников из меню с проверкой и запасными копиями.
- Удаление (`--uninstall`): службы, правила, туннели, команды, баннер; `--purge` — и папка с ключами.

## 8. Свой VPS

- Автонастройка по SSH: сборка из официальных исходников, ключи, обфускация (случайная или из рабочего конфига), автозапуск, `client.conf` на роутер.
- Защита: автообновления, fail2ban, вход по ключам (ключ роутера может быть добавлен на VPS); ufw не включается.
- Смена ключей туннеля с автоматическим откатом.
- Аудит VPS (`audit-server.sh`).

## 9. Качество

- Тесты на заглушках без роутера: `bash tests/run.sh` (сторож, guard, awg-self, iptables под блокировкой, удаление, установщик, обновление со старых версий).
- CI: синтаксис, shellcheck, тесты, `install.sh.sha256`, совпадение гайда со скриптами, отсутствие сторонних источников бинарников.
