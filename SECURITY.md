# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Сообщите приватно через GitHub: вкладка **Security → Report a vulnerability** этого репозитория (Private vulnerability reporting). Опишите, что можно сделать, при каких условиях (из LAN, с паролем панели, с доступом к VPS и т. п.) и как воспроизвести. Не прикладывайте свои ключи, токены и конфиги с `PrivateKey`: для диагностики есть обезличенный отчёт `awgctl report`.

Ответ — в течение 7 дней. Исправление выходит отдельным релизом с записью в CHANGELOG; благодарность — по вашему желанию.

## Модель угроз

**Что защищаем.** Закрытые ключи туннелей (`/data/awg/*.conf`), пароли и 2FA панели (`web/users.json`), токены API, токен Telegram, пароль автокопии, доступ к своему VPS (ключ роутера `ssh/id_ed25519`), а также то, что трафик выбранных устройств не уходит мимо туннеля (kill switch).

**Кому доверяем.** Администратору роутера (root по SSH) — полностью. Пользователям панели — в рамках их пароля: любой вошедший пользователь — администратор набора. Токенам API — только чтение или управление каналами, без доступа к учётным данным, ключам, копиям, перезагрузке и настройкам панели. Своему VPS — как серверу туннеля. Серверу провайдера VPN — только как точке выхода: его ключи и параметры набор не меняет.

**Границы.**
- Панель слушает только LAN-адрес роутера и принимает запросы только из частных сетей (`WEB_ALLOW`); HTTPS, PBKDF2-SHA256, TOTP, CSRF, проверка Origin и Host (защита от DNS rebinding), блокировка подбора, ограничение частоты API, строгая CSP без внешних ресурсов. Опасные действия (перезагрузка, удаление туннеля, импорт настроек, изменения на VPS, время сеансов) — с повторным вводом пароля.
- Секреты хранятся с правами 600; в браузер не возвращаются (пароли MQTT, автокопии, токен ntfy, путь вебхука); в аргументы `curl` и `ssh` не попадают (передаются через stdin), в журналы и отчёты — тоже.
- Бинарники AmneziaWG — только из официальных исходников `github.com/amnezia-vpn`, сборка на вашем сервере или с проверкой `SHA256SUMS`. Обновление набора — со сверкой SHA-256 (`install.sh.sha256`, архив релиза с `SHA256SUMS`).
- Набор не меняет настройки UniFi и не занимает его порты; правила встраиваются в штатные цепочки PBR и проверяются `awgctl drift`.

**Вне модели.** Компрометация самого UniFi OS или root на роутере; физический доступ; злоумышленник с паролем панели (он и есть администратор); вредоносный сервер провайдера VPN (видит ваш трафик по определению); публикация панели в интернет в обход `WEB_ALLOW` и проброса портов.

## Что уже сделано для проверки

- Тесты на заглушках для всех служб, панели (включая токены, CSRF, сеансы, частоту запросов), установщика и отката; CI на Python 3.7–3.12 и aarch64.
- `awgctl selftest`, `awgctl drift`, `/data/awg/audit.sh` и `server/audit-server.sh` — только чтение, показывают отклонения от ожидаемой конфигурации.
