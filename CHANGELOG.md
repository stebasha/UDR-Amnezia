# Журнал изменений

## 1.7.1 — не выпущено

**Меньше нагрузки на роутер**
- Сторож каналов, awg-guard, awg-self и awg-subnets проверяют состояние по одному снимку правил за проход и почти не запускают внешних процессов (`date`, `ip link`, `grep`, `sed` заменены средствами bash): в 4–20 раз меньше процессов в секунду.
- Сторож: пока по каналу идёт трафик, HTTPS-проверка не нужна (настоящая — не реже раза в минуту, `CHECK_MAX_AGE`); верная таблица маршрутов не переписывается каждый проход.
- Панель, бот, Home Assistant и метрики: состояние всех служб и handshake всех туннелей — одним вызовом.
- Бот: одна и та же проверка не запускается повторно, пока идёт прежняя; не больше двух тяжёлых проверок сразу. Панель: не больше четырёх фоновых задач сразу.
- Панель: зависшая команда снимается по сроку вместе с потомками (curl, ping), даже если ничего не выводит.

**Безопасность**
- Настройки из панели не могут записать в файлы, которые читает bash, ничего исполняемого (`$( )`, обратные кавычки, кавычки, перевод строки).
- Токен API не меняет, куда идёт трафик: конфиг туннеля, новый туннель, импорт и откат версии — только после входа по паролю.
- Вход не выдаёт по времени ответа, есть ли такое имя; отрицательная длина запроса — сразу ошибка.
- Все загрузки (установщик, списки, сборка) — только по HTTPS, в том числе при переадресации.
- Списки: одно обновление за раз. Кнопка «Тест» в боте — только для туннелей.

## 1.6.0 — 14.10.2026

**Свой VPS без ручной настройки (#28)**
- «Настройки → Свой VPS» → «Подключить и настроить»: адрес, пароль root (один раз), имя туннеля и порт. Роутер сам кладёт свой ключ на VPS (пароль — только для первого входа, через `SSH_ASKPASS`, нигде не сохраняется и не попадает в аргументы и журналы), проверяет Ubuntu/Debian и root, собирает AmneziaWG из исходников amnezia-vpn, создаёт сервер, забирает конфиг клиента, добавляет туннель и проверяет handshake и интернет. Конфиг клиента и скрипты на VPS удаляются. Без handshake — подсказка открыть UDP-порт в файрволе хостера. По SSH: `awgctl vps setup [ИМЯ] [ПОРТ]`.

**Бинарники из панели (#29)**
- «Свой VPS» → «Добавить ключ роутера»: для уже настроенного VPS — пароль root один раз, роутер добавляет свой ключ, сервер не меняется (`awgctl vps addkey`).
- «Проверить AmneziaWG» → «Обновить на роутере»: последние релизы собираются на своём VPS по ключу роутера, ставятся со сверкой `SHA256SUMS` и откатом, если пропал handshake. По SSH: `awgctl vps router-bins`.

**3x-ui: AmneziaWG 3.1 (#30)**
- «Настройки → 3x-ui»: адрес панели (с секретным путём) и API-токен (область admin; в 3x-ui «Учетная запись → Токен API»), при необходимости — без проверки самоподписанного сертификата. «Создать туннель»: в 3x-ui ≥ 3.8.5 появляется подключение AmneziaWG 3.1 с одним клиентом — роутером; закрытый ключ создаётся и остаётся на роутере, в 3x-ui уходит только открытый. Конфиг (S3/S4, диапазоны H, I1, HeaderProtectionKey и остальные параметры 3.1) собирается из ответа API, туннель добавляется дополнительным с проверкой handshake. «Убрать» удаляет и туннель, и подключение в 3x-ui. Нужен amneziawg-go v3.x на роутере — панель подскажет обновить.

**Несколько VPS и панелей 3x-ui, привязка существующего подключения (#32)**
- 3x-ui: панелей может быть несколько («Ещё панель»), у каждой — свой адрес, токен и название; настройки одной панели из 1.6-beta переносятся сами (`xui.json`, 600). Список подключений AmneziaWG каждой панели: адрес (с учётом узлов и `shareAddrStrategy`, как в ссылках 3x-ui), клиенты, трафик и какой туннель роутера на что ведёт.
- «Привязать»: уже работающий туннель роутера (например, запасной на inbound «Home») связывается со своим подключением по ключу сервера и порту — без пересоздания и без изменения сети. «Обновить из 3x-ui» переносит на роутер параметры, изменённые в 3x-ui (обфускация, ключ сервера, порт), с откатом, если туннель не поднялся; ключ и адрес роутера не меняются. «Отвязать» — только связь, туннель и подключение остаются.
- «Подключить»: туннель к уже существующему клиенту 3x-ui, если его ключ хранит 3x-ui. Убрать такой туннель — клиент в 3x-ui остаётся.
- 3x-ui 3.10: настройки подключения приходят JSON-объектом, а не строкой — раньше «Создать туннель» создало бы подключение, но не разобрало ответ. Теперь разбираются оба вида; при любой ошибке после создания подключение в 3x-ui удаляется. Учитывается общий ключ клиента (`PresharedKey`).
- Свой VPS: несколько серверов («Добавить VPS», выбор в списке; `awgctl vps list`, `awgctl vps --vps ID …`). Ключ роутера общий; мастер, проверка, состояние, версии, обновление, ключи и обфускация — для выбранного VPS. Настройки — `vps.d/ID.env`, основной — как раньше `vps.env`.
- Защита: смена ключей и обфускации через `vps.sh` не трогает туннели, привязанные к 3x-ui, и туннели не на порт `awg-server` (их сервер — 3x-ui); подсказка — менять в 3x-ui.
- `panel.py xui [ПАНЕЛЬ]` — подключения панелей 3x-ui и их связь с туннелями роутера, только чтение. `xui.json` и `vps.d/` входят в резервные копии.

**Разные туннели для разных устройств и доменов (#22)**
- «Настройки → Маршруты»: какие устройства и домены куда идут, задаётся в UniFi правилами Policy-Based Routes на разные профили VPN Client; каждому профилю назначается своя цепочка туннелей AmneziaWG по приоритету. У каждого маршрута свой сторож (`awg-failover-ID`): переключение, возврат, качество, kill switch (blackhole в своей таблице), ручной выбор канала. Один туннель может служить нескольким маршрутам; при переключении соединения туннеля, которым пользуется другой маршрут, не сбрасываются. «Только для этого маршрута» — основной маршрут такие туннели не использует.
- Защита от утечек не выпускает в WAN и метки дополнительных маршрутов. Самопроверка проверяет сторожа и таблицу каждого маршрута. Туннель, входящий в маршрут, из панели не удаляется. Удаление маршрута возвращает трафик профиля в сам профиль UniFi.
- По SSH: `awgctl routes rails|list|add|set|remove|switch` (`routes.sh`); маршруты и их службы восстанавливаются после обновления прошивки и убираются при удалении набора.

**IPv6 через туннель — по желанию (#23)**
- «Маршрутизация → Защита от утечек → IPv6 устройств под PBR»: новый вариант «Через туннель» (по умолчанию по-прежнему «Блокировать»). Помеченный UniFi IPv6-трафик идёт в таблицу PBR IPv6 на активный туннель с NAT66 и MSS, если у туннеля есть IPv6-адрес (из Address конфига); иначе — мгновенный отказ (unreachable), и устройства переходят на IPv4. В WAN такой трафик не выпускается в любом случае. Свои правило и маршруты IPv6 сторож убирает при выключении; правила и маршруты UniFi не трогаются.

**Автоподбор параметров обфускации (#33)**
- «Инструменты → Подбор параметров обфускации» (`awgctl tune`, `obfs-tune.sh`): текущий набор и N новых — у каждого handshake, интернет, потери, задержка и скорость (5 МБ), итог — оценка и лучший набор. «Только роутер» меняет Jc, Jmin, Jmax — параметры мусорных пакетов, которые сервер не сверяет (amneziawg-go шлёт их до handshake, принимающая сторона отбрасывает): подходит для туннеля провайдера и 3x-ui. «Роутер и свой VPS» меняет и S1, S2, H1–H4 согласованно (`vps.sh obfs --file`). После подбора туннель возвращается на исходный набор; лучший ставится только по кнопке «Применить» (с паролем; для роутера — через историю конфигов). По умолчанию только на неактивном канале.

**Прочее**
- Подбор обфускации: ожидание handshake до 45 с, нерабочий набор пробуется второй раз, текущий набор меряется так же, как новые (на роутере часть наборов ложно показывала «нет связи»).
- `guard.sh check`: выключенная служба awg-guard — INFO, а не ложный FAIL.
- Окно подтверждения: понятно, что нужен пароль от веб-панели.
- Гайд (index.html) и README дополнены разделами 1.6: маршруты, IPv6 через туннель, автоподбор, свой VPS из панели, 3x-ui.
- `panel.py tunnel-add ИМЯ ФАЙЛ [НАЗВАНИЕ]`; общие `tunnel_add` и `tunnel_remove` для API, мастера VPS и 3x-ui. `panel.py` без аргументов снова печатает свою справку.

## 1.5.0

Обновление с 1.2–1.4: кнопкой в панели («Система и обновление») или `bash <(curl -fsSL https://raw.githubusercontent.com/stebasha/UDR-Amnezia/main/install.sh) --update`. Настройки, ключи и пользователи сохраняются; при сбое — автоматический откат. После обновления канал — stable (проверенные релизы с SHA256).

**Устойчивость**
- Смена прошивки UniFi (#9): версии UniFi OS и Network запоминаются в `.fwver`; при смене (проверка при старте сторожа и из on_boot.d) — полное восстановление служб, самопроверка, событие «Прошивка» в журнале (панель, бот) и итог в Telegram. В README — таблица проверенных версий.

**Установщик**
- Каналы обновлений (#8): stable — последний релиз GitHub (архив `udr-amnezia-vX.Y.Z.tar.gz` и `SHA256SUMS`, сумма проверяется, подменённый архив не ставится; если релизов нет — ветка main), beta — ветка main, своя ветка. `install.sh --channel stable|beta|ВЕТКА`; выбор в панели («Система и обновление»); старый `.channel` переводится автоматически (main → stable, другая ветка → своя ветка). Обновление из панели фиксирует проверенный релиз. Релизы собирает workflow `release` по тегу `vX.Y.Z` после тестов.
- Бинарники AmneziaWG (#11): `install.sh --bins-check` сравнивает установленные amneziawg-go и awg с последними официальными релизами github.com/amnezia-vpn (релиз, а если его нет — самый свежий тег); то же в панели — «Система и обновление → Проверить AmneziaWG». `install.sh --bins-update` собирает последние релизы из исходников amnezia-vpn на вашем VPS, `--bins-update ПАПКА` ставит готовые файлы с проверкой `SHA256SUMS`. После замены туннели пересоздаются; если туннель, у которого был handshake, не получил его за минуту — возвращаются прежние файлы (`*.prev`). Тег сборки берётся из `BUILDINFO` и запоминается в `.binsver` вместе с суммами файлов: `--version` не всегда показывает тег релиза.
- Убраны «площадки» совместимости с установщиками 1.0/1.1 (#19): обновление поддерживается с 1.2 и новее. С 1.0/1.1 — командой `bash <(curl …/install.sh) --update` (см. README). Начало `install.sh` снова можно править без подгонки байтов.

**Свой VPS (#13)**
- Панель: «Настройки → Свой VPS» и `awgctl vps …` (`vps.sh`): вход ключом роутера без пароля (адрес — ваш VPS из настроек, порт и пользователь — в `vps.env`), состояние сервера (`audit-server.sh`, только чтение, плюс нагрузка, память, место и версии AmneziaWG).
- Обновление AmneziaWG на VPS до последних релизов amnezia-vpn: сборка из исходников на сервере, прежние файлы сохраняются как `*.prev`; если туннели к VPS, у которых был handshake, его не получили — откат (`awg-server-build.sh`: сборка во временную папку, `RESTART=1`, `ROLLBACK_BINS=1`, теги в `/usr/local/share/amnezia-build.txt`).
- Смена ключей и новые параметры обфускации (Jc, Jmin, Jmax, S1, S2, H1–H4) согласованно на обеих сторонах: копии перед изменением, проверка handshake и интернета через туннель, при неудаче откат и роутера, и VPS. Только для туннеля, у которого Endpoint — этот VPS; AWG 2.0 с диапазонами H не трогается. Изменения — отдельной службой с журналом в панели и только с паролем; событие «VPS» в журнале и уведомление.
- Скрипты для VPS (`vps-rotate.sh`, `audit-server.sh`, `awg-server-build.sh`) лежат на роутере в `/data/awg/server`. `vps-rotate.sh` умеет менять обфускацию (`OBF_FILE`).

**Уведомления (#14)**
- Вебхук и ntfy: те же события, что в Telegram (переключения, падения, возвраты, отчёт, перезагрузка, прошивка, сбой автокопии). Вебхук — POST JSON `{"source","host","level","time","text"}` (level: critical / warning / ok / info), необязательный заголовок для авторизации; ntfy — тема на ntfy.sh или своём сервере, приоритет по уровню, токен. Работают и без Telegram; отправка обычным маршрутом роутера, так что подходят адреса в LAN.
- Панель: «Настройки → Telegram → Вебхук и ntfy», тестовое сообщение. Путь вебхука, заголовок и токен ntfy в браузер не возвращаются (`hooks.env`, 600), curl получает их через stdin. `notify.sh --only telegram|hooks`.

**Резервные копии (#12)**
- Автокопия вне роутера: по расписанию (ежедневно или еженедельно, ночью; пропущенный запуск — после включения), шифруется паролем автокопии (`backup.pass`, 600), после создания проверяется расшифровкой. Отправка на свой VPS (scp ключом роутера, без пароля; запись во временный файл, сверка SHA-256 на сервере, затем переименование; на VPS хранятся последние N) и/или документом администраторам в Telegram (зрители не получают). Хранение на роутере — последние N (было всегда 7).

Сбой — событие «Копия» в журнале и сообщение в Telegram; `awgctl selftest` предупреждает, если последняя автокопия не удалась или устарела.

**Home Assistant (#5)**
- Служба `awg-ha`: MQTT discovery (MQTT 3.1.1 на стандартной библиотеке, логин/пароль, TLS с проверкой или без, LWT «offline»). Устройство «UDR-Amnezia»: активный канал, состояние, замечания, kill switch, процессор, память, температура, свободно в /data; по каждому туннелю — связь, handshake, RTT, потери, трафик; select «Канал» (авто / туннель), кнопки перезапуска туннелей; кнопка перезагрузки роутера — только при `HA_ALLOW_REBOOT=yes`. Набор сущностей пересобирается при добавлении/удалении туннелей. Брокер недоступен — переподключение с паузой до 5 минут, сторожу не мешает.
- Панель: «Настройки → Home Assistant» (брокер, логин, пароль не возвращается в браузер, TLS, префикс, период, проверка подключения, журнал службы); настройки в `ha.env` (600), входят в резервную копию.

**Панель**
- Безопасность (#21): ограничение частоты API с одного адреса (по умолчанию 1200 запросов и 240 изменений в минуту, `WEB_RATE` / `WEB_RATE_POST` в web.conf; сверх — 429 с Retry-After); время жизни сеансов настраивается («Активные сеансы»: без активности 5–1440 мин, всего 1–720 ч; применяется без перезапуска); удаление туннеля и импорт настроек — только с текущим паролем, как перезагрузка; журнал действий не обрезается, а ротируется в `audit.log.1` (просмотр и выгрузка показывают оба файла).

График трафика в обзоре: 10 мин / 24 ч / 7 дн / 30 дн, подписи датами; выгрузка CSV за выбранный период (`/api/history.csv?range=24h|7d|30d`).
- Сеансы переживают перезапуск и обновление панели (#7): хранятся в `web/sessions.json` (600), в файле только SHA-256 от токена — сам токен есть лишь в куке браузера. Прежние сроки (2 ч простоя, 12 ч всего), завершение по id и «остальные», сброс при смене пароля и удалении пользователя. В резервную копию сеансы не входят.

Токену никогда не доступны пароли, пользователи, 2FA, сеансы, сами токены, ключи туннелей (экспорт), резервные копии, перезагрузка, настройки панели, Telegram, импорт настроек и обновление. Неверные токены считаются как неудачные входы (5 за 10 минут → блокировка адреса на 15 минут). Действия пишутся в журнал от имени `token:имя`.

## 1.4.2

**Панель**
- Кнопка «Перезагрузить» в обзоре и на странице «Роутер»: перезагрузка роутера целиком с подтверждением текущим паролем. Перезагрузка запускается через 5 с отдельной службой (`systemd-run --unit=awg-reboot`), во время обновления набора недоступна; в журнале действий — `reboot` / `reboot-denied`, в событиях — «Перезагрузка», администраторам в Telegram — сообщение. Страница ждёт, пока роутер уйдёт и вернётся, и открывается сама.
- Выключение `awg-guard` в «Настройки → Службы» теперь ставит `LEAK_GUARD=no`, как и установщик. Раньше следующее сохранение настроек маршрутизации включало защиту обратно.

**Команды**
- `awgctl`, `awg-selftest` и `awgs` работают без интерактивной оболочки (`ssh роутер awgctl status`, PuTTY/plink, cron): ссылки в `/usr/local/bin`. Чужие файлы с теми же именами не трогаются; после обновления прошивки ссылки возвращает `awg-restore.sh`, при удалении — убирает `awg-uninstall.sh`.

**Исправления**
- `awg-selftest`: выключенные службы (`awg-subnets`, `awg-guard`, `awg-metrics`) больше не выдают «установлен, но не запущен» — служба считается включённой, если её юнит стоит в systemd или она есть в `.units`, а не просто потому, что копия юнита лежит в `/data/awg`.
- `awg-selftest`: без `LEAK_GUARD` в `awg.env` защита от утечек считается выключенной (как в `diagnose` и панели) — вместо ложного FAIL «не применена». Если `LEAK_GUARD=yes`, а служба выключена — WARN с подсказкой. Сообщение об IPv6 учитывает, работает ли защита на самом деле, и проверяет IPv6-маршрут в интернет, а не только адрес.
- `awg-notify.service`: остановка systemd больше не пишется в журнал как сбой (`status=143`, `Failed with result 'exit-code'`).
- `awgctl switch` писал «не переключилось», хотя переключение проходило: ждал один раз 7 с, а круг сторожа с проверками качества бывает дольше. Теперь ждёт до 30 с и отдельно сообщает, если сторож отклонил переключение; в панели и боте — так же (до 30 с вместо 10).
- `awgctl drift`: правило `TCPMSS --set-mss` сравнивается без числа (оно считается из MTU туннеля и меняется вместе с ним) — раньше после смены MTU была ложная тревога «пропало/появилось».
- Статистика «не на основном канале» (обзор, `awgctl stats`, бот): «Авто» больше не обрывает время на запасном (сторож остаётся на нём до возврата), а ручной выбор основного канала считается возвратом. Раньше 10 минут на запасном после «Авто» не учитывались.
- Панель: Esc закрывает только верхнее окно (раньше вместе со сравнением версий закрывался и редактор туннеля).
- Редактор туннеля: ошибки проверки («Не принято: …») прокручиваются в видимую область и дублируются уведомлением — раньше они появлялись под длинной формой незаметно.
- История версий конфига: «текущая» — только самая свежая совпадающая версия, остальные совпадения помечены «как текущая» и без кнопки «Вернуть».
- Панель в фоновой вкладке: при возврате на вкладку данные обновляются сразу, а не по таймеру (до минуты пустых графиков на странице «Роутер»).
- `awgctl diagnose` советовал несуществующую команду `awgctl domain-check`; теперь подсказка `awgctl domain`, а `domain-check` принимается как синоним.
- Сторож при старте сначала поднимает туннели, потом ставит маршрут: пропало «Cannot find device "awgmain"» в журнале при каждом перезапуске.

Светлая и тёмная темы, телефон.
- Безопасность: только LAN-адрес и частные сети, HTTPS (самоподписанный сертификат EC P-256), PBKDF2-SHA256, TOTP, сессии HttpOnly/SameSite=Strict с ограничением по времени, CSRF-токен и проверка Origin, защита от DNS rebinding (Host), 5 неудачных входов — блокировка на 15 минут, журнал действий, строгая CSP, ключи из конфигов в браузер не передаются, команды только из списка разрешённых, параметры проверяются.
- Только стандартная библиотека Python 3.7+, без внешних библиотек и CDN. Установка: мастер или «Компоненты → Службы и оповещения → Веб-панель»; пользователи и сертификат входят в резервную копию.

**Диагностика**
- `diagnose.sh` / `awgctl diagnose`: дерево причин (установка, WAN, каждый туннель — endpoint, петля маршрута, handshake, HTTPS, DoH, внешний IP, MTU; PBR — правило UniFi, таблица, blackhole; NAT/FORWARD/дубликаты/guard; IPv6; службы) с итогом «первая причина и команда исправления».
- `domain-check.sh` / `awgctl domain ДОМЕН`: правила набора для домена, адреса через DNS роутера и через DoH в туннеле, попадание в ipset, ответ HTTPS через туннель и напрямую, вывод.
- `report.sh` / `awgctl report`: обезличенный отчёт для issue (ключи, токены, chat id и публичные IP скрыты).
- Сторож: проверка HTTPS по всем адресам `TARGETS` перед ping, раз в минуту — DNS через туннель (DoH) в состоянии; `ip rule` с `proto 99`; правила читаются один раз за круг (меньше нагрузки на блокировку xtables).

## 1.2.0

**Исправления, найденные на живом роутере и при проверке**
- Все вызовы `iptables`/`ip6tables` идут с `-w`: без него iptables 1.8.7 (legacy) при занятой блокировке xtables сразу завершался ошибкой, проверка `-C` ошибочно отвечала «правила нет», и копии правил копились неделями. Правило теперь добавляется только при ответе «правила нет» (код 1); при занятой блокировке ничего не меняется до следующего круга.
- Сторож при старте и `--update` убирают накопившиеся дубликаты (`awgctl dedup`); `awg-audit` и `awgctl selftest` показывают их по всем таблицам и для `ip rule`.
- `self.sh check` больше не выдаёт ложное предупреждение про DNS-сервер роутера.
- Цепочки AWG_SELF и awg-guard не подменяются наполовину собранными; переходы в цепочки ровно одни и на своём месте; пропавшие (после перепровижнинга UniFi) цепочки восстанавливаются; параллельные запуски разделены блокировками.
- Kill switch: `blackhole` ставится при старте сторожа и остаётся при остановке и перезапуске (полностью убирает только `failover.sh cleanup all` / удаление).
- При переключении канала сбрасываются записи conntrack прежнего туннеля (UDP-потоки больше не зависают на старом адресе).
- `awg-detect.sh` обновляет в `awg.env` только таблицу, метку, приоритет и рельсу; раньше файл перезаписывался и терялись остальные настройки.
- Смена метки или таблицы PBR профилем UniFi обнаруживается: журнал сторожа, панель, аудит, самопроверка.
- Установщик и службы заменяют файлы через временный файл и `mv`, вход в установщик — функция `main`: обновление больше не может подсунуть работающему bash кусок нового файла. Для обновления с 1.0/1.1 в файле есть «площадка», на которой старый процесс спокойно завершается.
- Удаление и выключение служб: сначала остановка, потом снятие правил (раньше 5-секундный цикл службы возвращал правила).
- Повторный запуск `awg-server-setup.sh` больше не оставляет сервер выключенным.

**Бинарники**
- Только официальные исходники AmneziaVPN (`amnezia-vpn/amneziawg-go`, `amnezia-vpn/amneziawg-tools`) на закреплённых тегах. Сборка для роутера: `server/awg-build-router.sh` (статически, arm64, `SHA256SUMS`, `BUILDINFO`) — на своём VPS по SSH из установщика или на любом компьютере с Ubuntu/Debian. Свой источник — только с SHA-256. Скачивание сторонних сборок убрано.
- `up.sh` сам разрешает имя сервера в `Endpoint` (и помнит последний адрес), поэтому статическая сборка не зависит от библиотек роутера.

**Новое**
- awg-self (из awg-ui-fix.sh): трафик самого роутера по правилам PBR, unifi.ui.com из РФ через туннель. Мимо туннеля всегда: серверы туннелей (из всех конфигов), DNS роутера, DHCP, подсеть провайдера, ответы на входящие соединения. Файл dnsmasq проверяется `dnsmasq --test`.
- awg-guard: защита от утечек IPv4/IPv6, домены через туннель (IPv6-адреса доменов отклоняются) и исключения.
- Сторож: несколько туннелей (`TUNNELS_EXTRA`), выбор по качеству, ручное переключение, `events.log`.
- `awgctl`, `awg-selftest` (`--full` — живая проверка kill switch), подбор MTU, зашифрованные резервные копии, бот Telegram и недельный отчёт, метрики Prometheus.
- Установщик: `--selftest`, `--dry-run`, `--verify`, `--self-update`, `--record`/`--answers`, `--rotate-keys`, `--harden-vps`, обновление бинарников из меню, автовосстановление через on_boot.d, ключ роутера для входа на свой VPS.
- Подсети VPN-сервера — файлом `awg/subnets.sh` и службой `awg-subnets` (раньше генерировались установщиком); старый способ через ipset `UBIOS4local_network` больше не используется.
- Тесты на заглушках (`tests/`), CI, синхронизация скриптов в гайде (`tools/sync-guide.py`).
